# iDuckPDF

Free PDF tools in the browser: join, cut, arrange, sign, fill in forms, protect, read scans (OCR), convert to and from Word, Excel, PowerPoint and web pages, shrink, clean and compare PDFs. 48 tools, no sign-up, no watermark.
Built with **Expo (React Native + react-native-web)**, so one codebase serves the website today and can become the Android / iOS apps later.

- Engines: [`pdf-lib`](https://pdf-lib.js.org) for editing and [`@cantoo/pdf-lib`](https://github.com/cantoo-scribe/pdf-lib) (a fork with AES-256 encryption, loaded only by the password tools), [`pdf.js`](https://mozilla.github.io/pdf.js/) for rendering and text, [`Tesseract.js`](https://tesseract.projectnaptha.com) for OCR, JSZip for ZIP and Office files. A small layout engine (`src/engine/layout.ts`) draws Word, HTML and Excel content into PDF pages.
- Everything runs in the browser tab. The only exceptions are the two AI tools, which call the provider the user configures, with the user's own key. There is no server for files.
- Status and open items: [`docs/TRACKER.md`](docs/TRACKER.md) and [`docs/TODO.md`](docs/TODO.md). For a visual overview with every phase, what is pending from the owner and what Claude can do alone, open [`docs/status.html`](docs/status.html) in a browser (light and dark; the tool table is regenerated by `npm run status`).
- Earlier HTML prototypes live in [`prototype/`](prototype/).

## Run it
```bash
npm install                  # also copies pdf.js and the OCR engine + language data into public/vendor (git-ignored)
npm run web                  # dev server (needs a few GB of free RAM)
npm run export:web           # production build: clean -> tool metadata -> seo files -> static export -> SEO tag injection -> dist/
npm run audit                # crawler-style SEO audit of dist/ (run after export:web)
npm run typecheck            # also regenerates src/tools/meta.generated.json and src/content/guides.index.json
npm run meta                 # regenerate those light indexes and the tool table in docs/status.html (run after editing src/tools/ or src/content/guides.ts)
npm run test:engine          # 169 Node tests: the PDF engine, signing geometry, every Office/web conversion, and the picture tools
npm run serve:dist           # serve dist/ on http://localhost:8080 (gzip, extensionless pages, 404.html)
npm run e2e                  # browser tests against the served site (with its real Content-Security-Policy): 28 site checks + 85 tool checks. Needs Chromium: npx playwright-core install chromium; BROWSER=firefox or webkit runs them in another engine
node scripts/health-check.js # live-site health check: every sitemap URL, redirects, headers, canonicals (default https://iduckpdf.com)
npm run indexnow -- --all # IndexNow: tell Bing and others about the sitemap URLs (CI does this after each deploy to main)
npm run icons                # regenerate the duck icons and social card (outputs are committed)
```
Do **not** preview `dist/` with `serve -s` (single-page fallback): it answers every URL with the home page and hides the per-page HTML; use `npm run serve:dist`. Set `BASE_URL` to run the browser tests against another address (for example the live site).

### How SEO works here
- `output: "static"` pre-renders every route (tools and guides via `generateStaticParams`).
- Expo's `<Head>` is dropped during static export and a custom `+html.tsx` removes the app bundle, so neither is used. Instead `src/lib/seoData.ts` (`seoForPath`) is the single source for each page's title, description, canonical, robots rule and JSON-LD, and `scripts/inject-seo.ts` writes them into every HTML file after the build (and a small `seo-pages.json` that the app reads when someone navigates inside it, so no SEO text is in the JavaScript bundle).
- `src/content/` holds the tool copy, guides, legal pages and home FAQ. `scripts/gen-seo.ts` builds `sitemap.xml`, `llms.txt`, `llms-full.txt` and `public/_redirects` from the same registries, so they cannot drift.
- Links must be real anchors: use `Btn`/`Chip`/`ToolCard`/`LinkCard` with `to=`, never a bare `router.push`.
- Web theme colours are CSS variables and width-dependent layout is CSS (`src/lib/themeColors.ts`, `src/lib/responsive.ts`), so pre-rendered pages never flash or shift. New styling that depends on theme or width must follow that pattern.

## Deploy
Hosted on Cloudflare Pages (project `iduckpdf`). **Merging a pull request to `main` deploys** through `.github/workflows/deploy.yml`: typecheck, Node tests, build, SEO audit, browser tests, then deploy. A pull request runs everything except the deploy. A manual deploy is possible:
```bash
npm run export:web && npx wrangler pages deploy dist --project-name iduckpdf --branch main
```
Sign in once with `npx wrangler login`. `functions/` is bundled automatically. The workflow needs the `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` repository secrets. Domain and DNS notes are in `docs/TODO.md` §3.

## Layout
```
src/app/        screens (Expo Router): home, pdf-tools, [slug] (one page per tool), guides, chat, feedback, request, donate, roadmap, settings, about, privacy, terms
src/tools/      one file per group of tools (join, arrange, markup, convert, shrink, privacy, insight, secure, sign, ocr, office, sheets, slides); all.ts lists them, index.ts is the light registry
src/engine/     PDF helpers, file I/O, pdf.js + canvas helpers, layout engine, Office readers/writers (docx, xlsx, pptx), OCR loader (*.native.ts are stubs for the future apps)
src/ui/         themed building blocks, tool screen, sidebar shell, signature/placement/form editors
src/content/    tool SEO copy, guides, legal pages, home FAQ, tool URL slugs, changelog (plain TS, also read by the build scripts)
src/lib/        theme, command palette, storage, AI client, mail helper, SEO data
functions/      Cloudflare Pages Function: POST /api/donate (Dodo Payments checkout)
scripts/        gen-seo, gen-tool-meta, gen-status, inject-seo, gen-csp, audit-seo, health-check, indexnow, copy-vendor, make-icons, serve-dist, test-engine, test-office, e2e-smoke, e2e-tools
public/         robots.txt, manifest, _headers, _redirects (generated), icons, og.png; llms files, sitemap and vendor/ (pdf.js, OCR) are generated
```

## Adding a tool
1. Add a `ToolDef` to a file in `src/tools/` (inputs, options, `run`) and list it in `src/tools/all.ts`. Heavy libraries must be imported inside `run()` (or live in the lazy engine chunk), never at the top of a page.
2. Give it a URL in `src/content/toolSlugs.ts`: it must contain "pdf", or `npm run meta` fails.
3. Add its copy to `src/content/toolSeo.ts` (answer-first summary, steps, uses, FAQ) and, ideally, a guide in `src/content/guides.ts`.
4. Add Node tests (`scripts/test-engine.ts` or `scripts/test-office.ts`) and browser checks (`scripts/e2e-tools.js`).
5. Run `npm run typecheck`, `npm run test:engine`, `npm run export:web`, `npm run audit`, `npm run e2e`. It then appears in the sidebar, palette, home page, helper, search, sitemap and `llms.txt` automatically.

## Releases
- Every change goes on a branch and a pull request. CI must be green before merging; if it fails, fix it on the same branch. Merging to `main` deploys.
- The Content-Security-Policy is generated at build time by `scripts/gen-csp.ts` (inline scripts allowed by hash, no `unsafe-inline` for scripts) and written into `dist/_headers`; the audit and the browser tests check it. If you add an inline script, an outside script host or a new connection target, the policy must allow it.
- Old `/tool/<id>` and `/tools` addresses are redirected (generated `public/_redirects`).
- Docs ride along with the change that needs them: update `docs/TRACKER.md`, `docs/TODO.md` and `docs/status.html` in the same pull request.
- At the end of a work session run the `docs-sync` skill (`.claude/skills/docs-sync/SKILL.md`): it re-measures the figures and brings the status page, tracker, TODO and README in line in one pull request.
